# Rust Laboratory: Signal Zero — مشخصات محصول و معماری نسخهٔ ۱

> **جایگاه محصول:** یک معمای رواییِ رومیزی برای ویندوز که کشف، انتخاب و استنتاج را در یک آزمایشگاه متروک ترکیب می‌کند. محصول قرار نیست ابزار ساخت بازی یا رمان تعاملی عمومی باشد؛ تمرکز آن روی یک تجربهٔ کوتاه، خوش‌ساخت و چندباربازی‌پذیر است.

## تجربهٔ بازیکن

بازی‌کننده در نقش بازرسِ بازیابی اطلاعات وارد «آزمایشگاه آرگون» می‌شود؛ خاموشی سامانه، پیام‌های ناقص و دسترسی محدود او را وادار می‌کنند مسیرهای آزمایشگاه را باز کند، شواهد را کنار هم بگذارد و دربارهٔ سرنوشت یک نمونهٔ هوشمند تصمیم بگیرد. هر صحنه باید یک هدف روشن، دست‌کم یک کنش معنادار و یک بازخورد فوری داشته باشد.

| صفحه / ناحیه | هدف کاربر | رفتار نسخهٔ ۱ |
|---|---|---|
| صفحهٔ آغاز | شروع سریع یا ادامهٔ آخرین ذخیره | «پروندهٔ جدید»، «ادامه»، «تنظیمات» و یک خلاصهٔ بصری از وضعیت آخرین ذخیره. |
| نوار رویداد | خواندن روایت و پیامد انتخاب | متن با کنتراست بالا، تایپوگرافی خوانا، پیمایش صفحه‌کلید و ثبت رویدادهای مهم. |
| پنل انتخاب | تصمیم‌گیری بدون فرمان‌نویسی | دکمه‌های شماره‌دار با پیش‌نیازِ توضیح‌پذیر؛ انتخاب غیرقابل‌استفاده علت خود را نشان می‌دهد. |
| نقشهٔ آزمایشگاه | مکان‌یابی و برنامه‌ریزی | اتاق‌های کشف‌شده، موقعیت جاری، قفل‌های قابل‌بازشدن و خروجی‌های مجاز؛ بدون لو دادن اتاق‌های کشف‌نشده. |
| پروندهٔ شواهد | تبدیل سرنخ‌ها به استنتاج | موجودی، شواهد، هدف فعلی و پیشرفت پایان‌ها؛ هر شواهد توضیح کوتاه دارد. |
| نوار وضعیت | اعتماد و پیشرفت | نام مکان، انرژی/دسترسی، شمار سرنخ و نشان «ذخیره‌شده». |

## اصول دسترس‌پذیری و بومی‌سازی

رابط باید با صفحه‌کلید به‌طور کامل قابل استفاده باشد و اندازهٔ متن، کنتراست بالا، کاهش حرکت و بی‌صدا کردن صدا را در تنظیمات نگه دارد. متن داستان از اجزای رابط جدا می‌شود. نسخهٔ ۱ انگلیسی است، اما کلیدهای رابط و محتوا از ابتدا قابل ترجمه‌اند تا افزودن زبان‌های بعدی، از جمله فارسی راست‌به‌چپ، نیازمند بازنویسی منطق نباشد.

## معماری

```text
src/
  main.rs             نقطهٔ ورود و پنجرهٔ eframe
  app.rs              وضعیت رابط، صفحه‌ها و کنترل صفحه‌کلید
  game.rs             وضعیت دامنه، انتخاب‌ها، شروط، پایان‌ها
  content.rs          بارگذاری و اعتبارسنجی محتوای JSON
  persistence.rs      ذخیره/بارگذاری نسخه‌دار و تنظیمات محلی
  theme.rs            رنگ، تایپوگرافی و اجزای مشترک
  tests.rs            آزمون‌های یکپارچه برای مسیرهای داستان
assets/
  story_en.json       جهان، گره‌ها، انتخاب‌ها و پایان‌ها
  app_icon.svg        منبع آیکن برنامه
docs/
  PRODUCT_AND_ARCHITECTURE.md
```

### مدل داده

هر گرهٔ داستان شامل شناسه، عنوان، متن، برچسب مکان، فهرست انتخاب‌ها و اثرهای آن‌هاست. یک انتخاب می‌تواند به گرهٔ بعدی برود، یک شاهد اضافه/حذف کند، یک پرچم منطقی تعیین کند یا سطح دسترسی را تغییر دهد. شرط‌ها به‌صورت داده‌ای بررسی می‌شوند و پایان‌ها از پرچم‌های شفاف نتیجه می‌گیرند. ذخیرهٔ بازی شامل نسخهٔ schema، گرهٔ جاری، شواهد، پرچم‌ها و تنظیمات رابط است؛ بنابراین در نسخه‌های بعدی قابل مهاجرت خواهد بود.

### تصمیم‌های فنی

| نیاز | انتخاب | علت |
|---|---|---|
| برنامهٔ ویندوزی بومی | Rust + `eframe/egui` | نصب ساده، مصرف پایین، کنترل کامل روی UI و هم‌زبانی با هستهٔ Rust. |
| محتوای قابل توسعه | JSON + `serde` | تغییر محتوا بدون تغییر منطق، آزمون‌پذیری و مسیر روشن برای ابزار نویسندگی آتی. |
| ذخیره‌سازی | JSON نسخه‌دار در پوشهٔ دادهٔ کاربر | شفاف، قابل پشتیبان‌گیری، بدون نیاز به سرور یا جمع‌آوری اطلاعات شخصی. |
| انتشار ویندوز | بستهٔ zip اولیه + installer در نسخهٔ بعدی | کاهش ریسک عرضه؛ نصب‌کنندهٔ امضاشده فقط پس از تثبیت نسخه و تأیید مالکیت گواهی. |
| تحلیل محصول | فقط دادهٔ محلی و رضایت‌محور | کاهش دامنهٔ GDPR/CCPA و حفظ اعتماد بازیکن. |

## معیار پذیرش نسخهٔ ۱

نسخهٔ ۱ زمانی قابل عرضه است که یک دور کامل بازی با حداقل سه پایان، پنج مکان قابل کشف، هشت انتخاب معنادار، چهار شاهد، ذخیره/بارگذاری، تنظیمات دسترس‌پذیری، اجرای کامل با صفحه‌کلید و تست‌های عبور از مسیرهای اصلی داشته باشد. هدف انتشار اولیه یک دمو در itch.io و سپس نسخهٔ پریمیوم Steam است؛ دمو باید یک پروندهٔ مستقل و پایانی رضایت‌بخش ارائه دهد، نه صرفاً قطع ناگهانی محتوا.
